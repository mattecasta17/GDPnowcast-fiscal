# GDPnowcast-fiscal — Structure / Reproducibility / Hygiene Audit

**Scope:** structure, file organization, reproducibility, data hygiene. **Out of scope:** code quality, statistical/econometric methodology.
**Mode:** read-only. No files were modified or committed.
**Date:** 2025-05-11.

---

## TL;DR

1. **209 MB repo, 97 MB of which is `.git`** — 1,041 `.xlsx`, 136 `.csv`, 70 `.pickle` artifacts are committed and there is **no `.gitignore`**. Every `git clone` pulls ~100 MB of binaries that should be regenerated or fetched.
2. **20 near-clone scripts** (`nowcast_2017.py` … `nowcast_2025.py` + the `_fiscal` twins): pairwise diff is only **~5–10 % of the file**, parametrized by 3 things (year, `Spec_US_new` vs `Spec_US_fiscal`, output dir suffix). Same story for the two ~50 KB Streamlit dashboards (diff ≈ 18 % of lines).
3. **Broken import.** `Functions/update_Nowcast2.py:6` does `from Functions.update_Nowcast import News_DFM` — but `Functions/update_Nowcast.py` is **not in the repo**. Every `nowcast_YYYY*.py` script transitively imports `update_nowcast2`, so the published code does not run as-is.
4. **Hardcoded absolute Windows paths** (`C:\Users\Matteo17\OneDrive\Desktop\Nova SBE\Tesi\Nowcasting\...`) inside every `nowcast_YYYY*.py` `param_map` and a **hardcoded FRED API key** in `variables_creation.py:25`. The repo is not portable and a secret is in git history.
5. **No tests, no entry point, no environment pinning.** `requirements.txt` exists (9 unpinned packages, missing `fredapi` and `python-dateutil`); README does not say how to actually run anything end-to-end.

## Quantified duplication

### `nowcast_2017.py` vs `nowcast_2018.py` (year axis)

- Total combined lines: 366 (193 + 173).
- `diff` size: 161 lines (87 unique on each side, mostly the `vintages_dict_2017/2018` and `param_map_2017/2018` literals).
- **What differs:** the year embedded in the dict name, the GDP advance-estimate dictionary, the vintage date strings, and the pickle paths for prev/curr params. **Everything else is byte-identical.**
- Estimated functional similarity: **~92 %**. The only true parametrization is `(year, vintages_per_quarter, ground_truth_gdp, param_map)`.

### `nowcast_2017.py` vs `nowcast_2017_fiscal.py` (fiscal axis)

- Total combined lines: 373.
- `diff` size: 124 lines.
- **What differs (literally, line by line):**
  - `Spec_US_new.xlsx` → `Spec_US_fiscal.xlsx`
  - `nowcast_Q` → `nowcast_Q_fiscal` (3 occurrences each)
  - `metrics_Q` → `metrics_Q_fiscal` (3 each)
  - `news_Q` → `news_Q_fiscal` (3 each)
  - `data/US_new` → `data/US_fiscal` (2 each)
  - `DFM_quarter_param/ResDFM_*` → `DFM_quarter_param_fiscal/ResDFM_fiscal_*` (8 each)
  - Output filenames get a `_fiscal` suffix.
- **The fiscal twins drift over time** (2017_fiscal lacks the `load_res_cached` helper that 2017 baseline has; 2018_fiscal probably has a slightly different pickle-load pattern). This is exactly the "copy-paste then patch independently" trap.
- Estimated functional similarity: **~90 %**. Single parametrization: `variant ∈ {'new', 'fiscal'}`.

### `nowcast_2024.py` vs `nowcast_2024_fiscal.py`

- `diff` shows **only** the same axis (specs / output dirs / pickle paths). Pure mechanical copy.

### Dashboards

- `dashboard_nowcast_new.py` (1,166 ln) vs `dashboard_nowcast_fiscal.py` (1,469 ln).
- `diff` = 523 lines. Fiscal dashboard adds 3 series to `variable_dict` and an extra ~300-line block of fiscal-specific charts. **Otherwise ~82 % identical.**

### Conclusion on duplication

The 20 nowcast scripts collapse to **one CLI script with 3 arguments**: `--year`, `--variant {baseline,fiscal}`, plus a YAML/JSON of vintages per quarter. The two dashboards collapse to **one Streamlit app** with a `variant` toggle and a fiscal-feature flag.

Lines that could be removed from the repo: roughly **20 × 7 KB - 1 × 9 KB ≈ 130 KB of duplicated nowcast code**, plus ~40 KB of duplicated dashboard code → **~85 % of the root-level Python files**.

- To reproduce the full results from scratch a user would have to (a) acquire 971 vintage xlsx files (b) run `DFM_new.py` (which estimates only ONE vintage `2016-10-03` per default, with the rest hard-coded in `DFM_fiscal.py` as a single 34-entry list) (c) run each of 18 `nowcast_*.py` scripts in order (d) run `variables_creation.py` to enrich fiscal data… — and adjust ~80 absolute Windows paths first.

### Tests

- **No `tests/` directory.** No `test_*.py` anywhere.
- `Functions/dfm.py:84` contains `# TODO: ... after the unit tests are created` — acknowledged but not done.

### Documentation

- + Cites the upstream FRBNY/MK projects, gives dashboard links.
- + Explains the `_new` / `_fiscal` convention.
- + Lists folder roles.
- − No "How to run" section.
- − No mention of `requirements.txt` (or how to set up the env).
- − No mention of `Functions/`, `variables_creation.py`, or how vintages are obtained.
- − No FRED API key setup instructions (but the key is in the code, so it "works"…).
- − No mention of `Results.pdf` content.

Missing entirely. Confirmed by two `Glob` searches.

## Proposed target structure

The project has exactly **two pipelines** (estimate DFM, run nowcast) × **two variants** (baseline, fiscal) × **N years**. A clean refactor collapses this to:

```
gdpnowcast-fiscal/
├── README.md                           # how to install, fetch data, run, reproduce
├── LICENSE
├── pyproject.toml                      # pinned deps, package metadata (replaces requirements.txt)
├── .gitignore                          # see below
├── .env.example                        # FRED_API_KEY=...  (real .env is gitignored)
│
├── src/
│   └── gdpnowcast/                     # importable package; was "Functions/"
│       ├── __init__.py
│       ├── dfm.py                      # core DFM estimation (was Functions/dfm.py)
│       ├── data.py                     # vintage loader (was load_data.py)
│       ├── spec.py                     # spec loader (was load_spec.py)
│       ├── news.py                     # news decomposition (was update_Nowcast2.py, fixed import)
│       ├── nans.py                     # spline NaN imputation (was remNaNs_spline.py)
│       └── decomposition.py            # GDP common/residual (merges decompose_common_factor + extract_common_residual)
│
├── configs/
│   ├── spec_us_baseline.xlsx           # was Spec_US_new.xlsx
│   ├── spec_us_fiscal.xlsx
│   ├── vintages.yml                    # vintage dates per (year, quarter) — extracted from the 18 dicts
│   └── gdp_truth.yml                   # gdp_adv_estimate per quarter (currently scattered across 18 files)
│
├── data/                               # GITIGNORED (or LFS); fetched by scripts/fetch_data.py
│   ├── US_baseline/
│   └── US_fiscal/
│
├── outputs/                            # GITIGNORED
│   ├── baseline/
│   │   ├── dfm_params/                 # was DFM_quarter_param/
│   │   ├── nowcast/                    # was nowcast_Q/
│   │   ├── metrics/
│   │   └── news/
│   └── fiscal/
│       └── ...                         # parallel
│
├── scripts/                            # thin CLI entry points
│   ├── estimate_dfm.py                 # python -m scripts.estimate_dfm --variant baseline --vintage 2017-01-03
│   ├── run_nowcast.py                  # python -m scripts.run_nowcast --variant fiscal --year 2024
│   ├── run_all.py                      # loops years 2017–2025 × variants
│   ├── fetch_fred.py                   # was variables_creation.py, keyless (FRED_API_KEY from env)
│   └── build_vintages.py               # rebuild data/US_*/{vintage}.xlsx from ALFRED if feasible
│
├── apps/
│   └── dashboard.py                    # single Streamlit app; --variant toggle via st.sidebar
│
├── tests/
│   ├── test_load_spec.py
│   ├── test_load_data.py
│   ├── test_dfm_smoke.py               # runs DFM on one tiny vintage end-to-end
│   └── test_news_decomposition.py
│
└── docs/
    ├── thesis_results.pdf              # was Results.pdf
    └── methodology.md                  # short text explaining baseline vs fiscal variant
```

### Rationale per choice

- **`src/gdpnowcast/`**: makes the library installable (`pip install -e .`), gives proper namespacing, breaks the bare-`from Functions.X import …` pattern.
- **Year/variant become CLI arguments**, not filenames. `nowcast_2017.py` … `nowcast_2025_fiscal.py` (18 files, ~130 KB) → one `scripts/run_nowcast.py` (~150 lines) that reads `configs/vintages.yml` and `configs/gdp_truth.yml`.
- **`configs/vintages.yml`** holds the ~36 quarter-vintage lists currently duplicated across 18 Python dicts.
- **`outputs/{variant}/{stage}/`** unifies the 8 sibling output dirs (`nowcast_Q`, `nowcast_Q_fiscal`, `news_Q`, …) under one tree, all gitignored.
- **`apps/dashboard.py`** with a `variant` toggle replaces the two ~50 KB dashboards. The ~300-line fiscal-specific block becomes a conditional in the same file.
- **`tests/`**: one smoke test for DFM, one for spec parsing, one for news decomposition. Required to unlock confident refactoring.
- **`.env` + `pyproject.toml`** replace the hardcoded API key + unpinned `requirements.txt`.
