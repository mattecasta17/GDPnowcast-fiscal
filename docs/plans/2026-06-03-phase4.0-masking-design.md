# Phase 4.0 — Target-masking mode for the backtest runner

**Branch:** `refactor/v2`
**Date:** 2026-06-03
**Author:** Matteo Castaldo (with AI assistance)
**Status:** Design approved (verbal, 2026-06-03) — written for review before `writing-plans`.

This is the **first, mandatory step of the Phase 4.0 evaluation-methodology gate** (see
`docs/plans/2026-05-11-v2-design.md` §3 Phase 4). It must land before any headline
RMSE/MAE backtest, because it changes what the final-vintage nowcast *is*.

---

## 1. Context & motivation

The backtest walks a quarter's weekly vintages and, on each contiguous `(old, new)`
pair, calls `update_nowcast` to produce `y_new` (the nowcast as of `new`). The headline
error is `gdp_actual − y_new`.

The problem is the **release-week vintage**. The BEA advance estimate for quarter *Q*
is published mid-/late in the first month after *Q* (for 2017Q1: 2017-04-28). On that
vintage the current-quarter GDP cell is **observed**, so in `News_DFM`
(`src/gdpnowcast/news.py:169`) the `~np.isnan(X_new[t_fcst, gdp])` test is True and the
**NO-FORECAST CASE** fires. That branch is *meant* to read the just-released advance back
out as the "nowcast" (→ error ≈ 0, meaningless) — but in the port it never even gets
there: it raises a **`ValueError`** at `news.py:179`, the `t_fcst`-array-into-scalar
shape bug in that branch. Either way the release-week vintage is unusable.

Today the runner doesn't even keep that vintage: v1 wrapped every pair in a blanket
`except`, and the release-week pair raises the `ValueError` above, so it is **dropped**.
(This is a *distinct* mechanism from the no-news weeks, which drop via a `None − None`
`TypeError` — see §4; `runner.py:63-64` and the golden's `reason` fields record both.)
The 2017Q1 output is therefore 18 rows whose last surviving row is **2017-04-21**,
*before* the final five releases of the quarter (2017-04-22 … 2017-04-28). So the "last
nowcast" we report is neither genuine on the release week (it would be a ≈0 read-back if
it didn't crash) nor the last available information set.

The NY Fed discipline is: **when nowcasting quarter *Q*, the GDP value for *Q* is never
in the information set.** You mask the target you are predicting; you keep everything you
need to predict it.

## 2. The fix — mask the single target cell

Before the smoother runs, set the **current-quarter GDP cell to `NaN`**:

```
X_new[t_nowcast, i_series] = NaN     # and X_old likewise
```

- `t_nowcast` is the row for the target quarter end (2017Q1 → 2017-03-01), the **same
  canonical index** `update_nowcast` already computes at `news.py:77-89`.
- `i_series` is the GDP column.

This is **one cell**. Everything else is untouched and used by the model:

- **all historical GDP** — Q4 2016 (2016-12-01), Q3 2016, … back to sample start. The
  model needs the last *observed* real GDP to anchor the factor.
- **all other series at all dates**, including the late releases 2017-04-22 … 2017-04-28
  — these are exactly what drive the genuine forecast.

There is no look-ahead exposure: future quarters are already `NaN` (not yet released),
and within one quarter's loop only the **advance** of that quarter ever arrives (the
preliminary/third revisions land in later months, outside the nowcast window). So there
is exactly **one** target cell per quarter. No backfill, no history removed — consistent
with the standing anti-look-ahead guardrail.

## 3. Approach — gated inside `update_nowcast`

Add `mask_target: bool = False` to `update_nowcast`. When True, set the target cell to
`NaN` in both `X_new` and `X_old` at the point where `t_nowcast` is known and `X_rev` has
not yet been built — i.e. after the `t_nowcast.size == 0` guard (`news.py:89`) and before
`X_rev = X_new.copy()` (`news.py:92`). (`t_nowcast` is assigned at `news.py:80/84`;
`i_series` at `news.py:74`.) `run_quarter` gains the same `mask_target=False` parameter
and threads it through.

Masking `X_old` as well is **inert for 2017Q1** — within a single quarter's loop `v_old`
is always a pre-release vintage, so `X_old[t_nowcast, gdp]` is already `NaN` (and
`X_rev[np.isnan(X_old)] = np.nan` at `news.py:93` would re-impose what masking `X_new`
already set). It is kept defensively: a future quarter whose vintage calendar runs past
the advance release could place a post-release vintage as `v_old`, where masking `X_old`
becomes load-bearing.

Rejected alternatives:

- **B — standalone helper masking `x_old`/`x_new` in the runner.** Keeps `news.py`
  pristine, but must **re-derive** the period→row mapping that `update_nowcast` already
  owns → drift risk if the two ever disagree on the target row.
- **C — a separate masked `update_nowcast`/`News_DFM` path.** Maximum isolation, maximum
  duplication of a 380-line numeric function → YAGNI.

Approach **A** is ~2 lines at the one place where the canonical target row is already in
hand; `mask_target=False` by default keeps the existing path byte-identical.

## 4. What changes, what stays identical

**Stays identical (default `mask_target=False`):**

- `test_news_golden.py` and `test_runner_golden.py` — the v1-parity goldens — are
  unaffected. The default path is unchanged.
- **Parameter estimation is not touched.** `run_quarter` estimates the prev/curr DFM on
  early-quarter vintages where the current-quarter GDP cell is *already* `NaN` (advance
  not yet out), so masking there would be a no-op. Masking lives only in the news step.

**Changes (only under `mask_target=True`):**

- **Pre-release vintages:** no-op. GDP for *Q* is already `NaN`, so masking changes
  nothing — those rows are bit-identical to the unmasked run.
- **No-news weeks** (2016-12-30, 2017-02-24): still skipped. They drop because *no*
  series brought new information (`v_miss` empty), which masking the target does not
  change. Correct — there is genuinely nothing to update.
- **Release-week vintage** (2017-04-28): flips from *dropped* to a **genuine nowcast
  row**. With GDP masked, the NO-FORECAST case no longer fires; the late non-GDP
  releases drive `News_DFM`'s FORECAST/new-information path, producing a real forecast of
  the masked target.

## 5. Effect on the 2017Q1 output

- Row count **18 → 19**. The new last row is **2017-04-28**, the genuine final nowcast on
  the full information set.
- The headline error becomes `gdp_actual − y_new(2017-04-28)` — the meaningful
  NY-Fed-style error, not the ≈0 read-back. **Preliminary** (one end-to-end run of the
  shimmed stack on the `US_new_v1` backup, during design review): `y_new ≈ 2.2461`, so
  error `≈ 0.7 − 2.2461 = −1.55`. To be **reproduced by the TDD run and pinned** (§6) —
  not taken as gospel from the review.
- Honest-research note: this changes the headline narrative versus v1 — the genuine
  final 2017Q1 nowcast (~2.2) is well above the 0.7 advance, a real ~1.5pp miss rather
  than the ≈0 read-back. We report what the masked pipeline produces, whatever it is.

## 6. Test plan (TDD, characterization)

There is no v1 oracle for masked output — it is new, correct behaviour. So:

1. **Default unchanged:** with `mask_target=False`, `run_quarter` output stays equal to
   the existing golden (the current `test_runner_golden.py` already pins this; it must
   keep passing untouched).
2. **Masked behaviour:** with `mask_target=True` on 2017Q1:
   - `2017-04-28` **appears** as a row (was skipped);
   - the two no-news weeks (`2016-12-30`, `2017-02-24`) **still** appear in
     `df.attrs["skipped"]`;
   - `y_new(2017-04-28)` is finite and **differs** from the advance read-back (`0.7`);
   - **pin** `y_new(2017-04-28)` (preliminary ≈ `2.2461` from §5 — reproduce and pin the
     exact value) and the other masked-run row values (at least the final row) as a
     characterization value, the way B6 pinned the common-share.
   - Marked `slow` + skip-if-no-`data/US_new_v1` backup, like the other heavy goldens.

Each masked assertion is written **red first** (failing because `mask_target` does not
exist / the row is still skipped), then made green by the gated change.

## 7. Out of scope (later in Phase 4 / Phase 4.0)

- **Thursday-vs-Friday vintage calendar** — the expensive now-or-never refetch. Tracked
  separately; masking is the priority and is independent of the calendar.
- **Other `CONFIG_*` quarters / full 2017-2025 backtest** — masking is built and verified
  on 2017Q1 first; the full re-run is the Phase 4 body.
- **Diebold-Mariano rewrite, power/MDE, benchmarks** — Phase 4 / 4.5, downstream of a
  correct masked backtest.
- **Data-panel truncate-vs-fuller** decision — separate open ⚑.

## 8. Acceptance for this step

- `update_nowcast` and `run_quarter` accept `mask_target` (default `False`).
- Default path: existing goldens pass unchanged.
- Masked path: 2017Q1 yields the 19-row result above, with the release-week row present
  and its `y_new` pinned.
- `just ci` (lint + mypy + fast tests) green; `just test-golden` green on the data backup.
