## 1. Context

The current repo (`develop_mattec` baseline = `main`) was written by Matteo during his Master's thesis at Nova SBE while still learning Python. A 3-agent audit (2026-05-11) of structure, code quality, and methodology identified:

- The DFM core is a **correct** Python port of the FRBNY Banbura-Modugno mixed-frequency DFM (Bok et al. 2018). Pseudo-real-time vintage backtest is methodologically sound.
- ~85% of root-level Python is **near-duplicate**: 18 `nowcast_YYYY[_fiscal].py` files, 2 ~1000+ line Streamlit dashboards.
- **3-4 methodology bugs** likely inflate the headline result ("fiscal variables improve nowcasting, especially Q2 and post-2020"):
  1. GCEC1 mis-aligned by 2 months vs GDPC1 in tent aggregation
  2. MTSDS133FMS loaded as raw `lin` (non-stationary, strong April seasonality) → "Q2 fiscal effect" is partly a calendar artefact
  3. Diebold-Mariano tests likely run at weekly granularity (N=575) instead of quarterly (T≈30), inflating significance by ~√22
  4. W875RX1 mis-labelled as "fiscal" (it's personal income ex-transfers, ρ=0.95 with DSPIC96 already in baseline)
- **2 reproducibility blockers:**
  - `Functions/update_Nowcast.py` is missing from the repo → all `nowcast_YYYY*.py` scripts fail with `ModuleNotFoundError` on clean clone. Results.pdf numbers cannot be reproduced from the public repo.
  - FRED API key committed in plaintext at `variables_creation.py:25` (already burned, must rotate).
- 144 hardcoded Windows paths, no `.gitignore`, no tests, 209 MB repo (97 MB `.git`), unpinned `requirements.txt`.

Full audit reports in `docs/audit/v1/`:
- `00_synthesis.md` — unified synthesis across the three audits
- `01_structure_audit.md` — folder structure + reproducibility
- `02_code_quality_audit.md` — Python code quality
- `03_methodology_audit.md` — statistical/econometric correctness

This document specifies a complete revision (v2) targeting both **portfolio piece** (primary) and **working paper** (secondary).

### Key structural decisions

- **`src/` layout** (not flat) — clean `pip install -e .`, no import conflicts with `scripts/`.
- **Distribution name `gdpnowcast-fiscal`**, import name `gdpnowcast` — explicit namespace to avoid PyPI collision.
- **`dfm.py` as a single file** (with `# region:` sections), NOT split into a sub-package. Splitting was deferred — we'll split only if after de-MATLAB-ization the file still exceeds ~800 lines AND there are clean boundaries. Premature splitting moves complexity without reducing it.
- **No `scripts/` directory** — replaced by `src/gdpnowcast/cli.py` (Typer) + `justfile` for one-liners.
- **No `vintages.yml`** — vintage dates computed at runtime via `fridays_between(start, end)`. Sample range lives in `configs/runtime.toml`.
- **Single config layer**: `configs/spec_us_*.xlsx` for signal specs (FRBNY-compatible) + `configs/runtime.toml` for runtime params. No YAML, no dataclass-as-config.
- **`docs/dashboard_data/`** committed (CSV/Parquet, ~5 MB) for Streamlit Cloud deploy. Live FRED fetching cannot be done from Streamlit Cloud (ephemeral disk, secrets management).
- **`outputs/` is fully gitignored**; paper figures live in `docs/paper/figures/` (committed).

## 5. Stack tooling

| Component | Choice | Notes |
|---|---|---|
| Python | **3.13** | Latest stable. |
| Package manager | **`uv`** (default), `conda` fallback | uv standalone, fast. If Matteo prefers conda for consistency, `conda create -n gdpnowcast python=3.13 && pip install -e .` works equally. |
| Build backend | `hatchling` | Modern default for `pyproject.toml`. |
| Linter + formatter | **`ruff`** | Replaces flake8 + isort + black. Pre-commit + CI. |
| Type checker | **`mypy`** with `disallow_untyped_defs=true`, NOT `--strict` | scipy types are spotty; strict creates more noise than signal. |
| Test runner | **`pytest`** + `pytest-cov` | Coverage target ≥70% on `src/gdpnowcast/`. |
| Pre-commit | **`pre-commit`** with ruff + ruff-format ONLY | Pytest in pre-commit slows commits; lives in CI instead. |
| CI | **GitHub Actions** | `test.yml` (pytest + ruff + mypy on push), `deploy-dashboard.yml` (Phase 5+). |
| Dashboard | **Streamlit** | Unchanged from v1. Deploy: Streamlit Community Cloud (free). |
| Plotting | `plotly` (dashboard interactive) + `matplotlib` (paper figures static) | Coexistence is clean. |
| DFM params persistence | **`np.savez_compressed`** + JSON sidecar (`schema_version: 1`) | Replaces fragile pickle. |
| Config validation | **`pydantic`** v2 | Validates `runtime.toml` + Excel spec at load. |
| Logging | **stdlib `logging`** + optional `rich` for dev output | structlog is overkill for research code. |
| Notebooks | `jupyterlab` optional | Only in `notebooks/`, non-load-bearing. |
| Task runner | **`just`** (justfile) | `just test`, `just fetch`, `just run`, `just dashboard`, `just paper`. |

## 6. Methodology scope per phase

### Phase 4 — Methodology fixes (all four bugs)

| Bug | Fix | Notes |
|---|---|---|
| GCEC1 mis-aligned (shifted 2 months, GDPC1 not) | **Remove the `shift(2)` on GCEC1**; both quarterly series at quarter-start (FRBNY convention) | Simpler than shifting both. |
| MTSDS133FMS loaded as `lin` (raw levels, seasonal) | **Default: `ch1` (12-month difference).** Fallback X-13 ARIMA-SEATS if Q2 stagionality survives | `ch1` is a one-cell edit in Excel; X-13 needs `statsmodels.X13ArimaAnalyzer`. |
| DM tests at weekly granularity (N=575) | **Quarterly final-week DM (T≈30 ex-2020) with Harvey-Leybourne-Newbold (1997) small-sample correction.** Bootstrap as robustness check | HLN is one extra line of math; bootstrap as sanity check, not headline. |
| W875RX1 mis-labelled "fiscal" | **Drop from fiscal block.** Paper discussion mentions "considered but rejected, ρ=0.95 with DSPIC96 already in baseline" | Honesty > inflated fiscal-block count. |

### Phase 6 — Validation rigor

| Component | Scope |
|---|---|
| Atlanta Fed GDPNow | Fetch via Atlanta Fed XLS direct download (free, no API key). Quarter-end alignment. |
| ARMA(1,1) | Fit on `pca(GDPC1)` with vintage selection (reuses ALFRED snapshot). |
| Forecast-encompassing | `(y_t − ŷ_baseline_t) = β (ŷ_fiscal_t − ŷ_baseline_t) + ε_t`, t-test on β=0, run at quarterly level. |
| Holdout split | Train spec on **2017-2022**, evaluate strictly on **2023-2025**. Report both numbers. |
| Predictive intervals | Convert `Vsmooth` (Kalman state covariance) → variance of GDP point forecast via delta method. Plot 68% / 95% bands. |
| SPF benchmark | **Best-effort** — skip if alignment proves messy; mention in "future work". |

### Phase 7 — Staff Nowcast 2.0 features

- **7a (mandatory): COVID factor + outlier vector** — unlocks 2020 from headline metrics. ~1-2 d.
- **7b (optional): long-run trend `g_t`** — useful for post-2020 baseline. ~2-3 d, only if Phase 7a runs under budget.
- **Excluded:** time-varying volatility (paper-only nice-to-have, not critical), full Bayesian estimation (5+ days, diminishing returns).

|---|---|

| Fixed legacy DFM (baseline, no fiscal) | After Phase 4 fixes, no fiscal vars |
| Fixed legacy DFM (with fiscal) | After Phase 4 fixes, with 2 fiscal vars (W875RX1 dropped) |
| DFM + COVID factor (with fiscal) | Phase 7a — includes 2020 |

## 8. Risks and open questions

### Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| FRED rate limits slow Phase 2 fetch (~450 vintages × 35 series ≈ 15,750 API calls) | Medium | Medium | Parallel fetching with bounded concurrency (4-8 workers), exponential backoff, resumable checkpoints. Sequential fetch is the v1 pattern; we'll parallelize. |
| Some FRED series may not have full vintages back to 2016-12 | Medium | Low | Drop or interpolate at fetch time, log warnings, document in `docs/data_sources.md`. |
| Phase 4 methodology fixes produce **worse** RMSE for fiscal variant (the "Q2 effect" was an artefact, headline collapses) | Medium | High | This is **honest research**, not a risk to mitigate. The paper narrative changes from "fiscal helps Q2" to "with proper preprocessing, fiscal contribution is marginal" — still publishable, more credible. |
| Streamlit Community Cloud has resource limits incompatible with our data size | Low | Medium | Pre-computed CSV/Parquet in `docs/dashboard_data/` keeps memory low (<100 MB). Test deploy on Phase 5. |
| Recovering `News_DFM` proves harder than expected (file truly lost) | Low | High (blocks Phase 3) | Fallback: re-implement from Bok et al. (2018) Appendix; cross-check with `MajesticKhan/Nowcasting-Python` (upstream). |
| Staff Nowcast 2.0 features require non-trivial state-space changes that break golden tests | High (in Phase 7) | Medium | Golden tests parametrized by `model_variant` from Phase 3, so Phase 7 adds new test cases instead of breaking existing. |
